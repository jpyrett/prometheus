8.  How to cache/fetch.  Call a langchanin ? no
Layer	Role
LangGraph / LangChain
Agent loop: reason, choose tools, stitch steps

MCP tools / resources
Capability boundary: quotes, filings, portfolio, calc

So LangGraph calls MCP (call_tool / read_resource).
 The MCP handler usually talks to APIs, DB, files, or your memory/ — not another LLM chain.

 When MCP → LangChain is fine

Retrieval/RAG behind a resource or tool (embeddings + vector search)
A heavy preprocessing pipeline you want hidden behind one tool name
When to avoid it

Resources — keep them cheap, deterministic reads (quotes, config). Don’t put an LLM chain in market://{symbol}/quote.
Nested “agent calls tool that runs another agent” — hard to debug, slow, costly.

Practical for Prometheus: LangGraph owns the desk workflow; MCP exposes market/portfolio/helpers. 
If a step needs an LLM, put that in the graph node, not inside every resource fetch

------
Resource handler = Redis GET (or similar) by key derived from the URI (market:AAPL:quote, etc.), return the payload. Fast, read-only, no LLM in the path.

LangGraph still sits above: it decides when to read_resource("market://AAPL/quote"); 
Redis is just where the bytes live.
 Tools stay for writes/actions (orders, updates that change Redis).
