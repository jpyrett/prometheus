# Show the price: a request that only asks for a stock's current quote (design choices entry 150)

Jacob, 2026-11-23: *"The app has a serious bug. It is not possible to get the direct current quote or stock price for a provided company. Such as: "Whats the current price of: <SYMBOL>? it has a bug where it finds the 7-day news instead and never just returns the stock quote from the API to show the latest price. Fix this"*

**Why it happens.** `TradeIntent.action` has four values (`buy`, `research`, `order`, `news`, entry 149). A request for a PRICE has none of its own, so the model reads "What's the current price of TSLA?" as the nearest one, `news` ("what's ABCD doing ..."), and the desk runs the news path: a 7-day news fetch and a cited summary, never a quote. The quote itself already exists and works: `DataClerk.request_quotes(order)` (entry 42; no model, Finnhub's `get_quote` per symbol, or the stored close with `USE_LIVE_TRADING=false`, entry 76). Nothing routes a user's request to it.

## 1. Rules

| # | Rule |
|---|---|
| Q1 | **A new action, `quote`.** `TradeIntent.action` takes `"quote"`: the person asks only for the current PRICE of one or more named stocks ("What's the current price of TSLA?", "What's the current price of: TSLA?", "Price of Tesla", "How much is MSFT trading at?", "Quote for AAPL and NVDA", "What's a share of Microsoft worth right now?"). THE MODEL reads it (no cue-word filter decides it, Jacob's rule). The prompt gets one bullet for it with made-up tickers, and the `news` bullet says that a request for the PRICE is `quote`, not `news`. A request that also asks to buy, sell, recommend, research or see the news ("what's TSLA's price, buy 5 if it's under $400", "price and news of TSLA") is NOT `quote`: the old actions keep their meaning (a request for the price AND the news is `news`, as today; open item 1). "What's TSLA doing the last week?" stays `news`. |
| Q2 | **What a `quote` intent may hold.** `symbols` and/or `companies`, 1 to `quote.max_stocks` (10), and NOTHING else: no topic (a theme has no price: "price of oil stocks" is a request to clarify, "name the stocks"), no orders, budget, `each`, count, even split, `raise_funds`, `max_price`, `min_price`, typed shares, `news_days`. The validator refuses each with its reason (the request is then one to clarify, entry 102). `as_direct_order` and every program that turns a `buy` into an `order` never touch a `quote` intent; `_read_numbers` is not run for it (a `$` in "is TSLA over $400?" is not money: such a request is still a quote, and the limit is not read). `describe()` says "show the current price of TSLA (nothing will be bought)". |
| Q3 | **The route.** On every desk: `account_manager -> data_clerk -> END`, exactly like `news` (`after_data_clerk` ends a `quote` plan; `path_finished` is `order.status == "data_ready"` for it, or the data_failed/clarify end as news has). The Advisor, the Critic, the decision, the funds node and the Trader are never on the path. Nothing reads or writes the account; no question in either mode; nothing is confirmed. The security screen at the first node is unchanged. |
| Q4 | **Naming the stocks.** The Data Clerk names them as for the news (`find_companies_of`, exact lookup and the brand rule of entry 101: "Tesla" is TSLA, Tesla Inc; "Google" is GOOGL). A name it cannot find is said with its reason; with no stock found the run stops and asks to clarify. |
| Q5 | **The quote, and only the quote.** The order is `action_type="fetch_quote"` (the existing action type `verify_quote_request` checks); the data_clerk node, after naming, sets `order.subject` to the listed symbols and calls the EXISTING `DataClerk.request_quotes(order)` once. No model call, no news fetch, no search, no bars refresh, no file is written. The run's fetch box (`fetch`) means nothing for a quote run (a quote is always the live lookup, or the stored close under `USE_LIVE_TRADING=false`). A symbol whose quote fails is named in `order.data.problems`; the others are still shown; with none the order is `data_failed` and the last message says why. |
| Q6 | **What is shown.** `views.quote_view(order, plan)` (pure) is the ONE shape the page and the session read: `{stocks: [{symbol, company, price, change, change_percent, open, high, low, previous_close, as_of_utc, simulated, source}], not_found: [{typed, reason}], problems, notes}`. Every number is the Data Clerk's, copied, never computed (the change is Finnhub's). `simulated: true` (the stored close) is said in words: "market close of 2026-11-20 (simulated clock)"; otherwise "live quote, last trade 15:59 ET". The run's last line (`finished`) is `status: "quote"`, headline "TSLA $412.30 (+1.24%)" (several stocks: each, joined by " · "), no trade, the portfolio unchanged. |
| Q7 | **The page: the MAIN OUTPUT WINDOW (Jacob, 2026-11-23: *"If just asked the price can return that in the main output window"*).** A live or replayed quote run emits a new event `quote` carrying `quote_view`, after the data_clerk node, and the price is shown in the run's main output (the output / last-message area every run already has): one line per stock, symbol, company, price, the change and percent, the time in words or the simulated note; then the not-found lines and problems. No new pane: the right column's toggle (entry 149) stays News | Work order and a quote run does not switch it. Text only, no `dangerouslySetInnerHTML`. The pipeline shows Account Manager and Data Clerk only. Mode, Strict, Neutral, Ignore Critic, Always raise funds and the fetch box change nothing on such a run. |
| Q8 | **The session.** `python -m prometheus.application.session` prints, for a quote run, one line per stock (symbol, company, price, change, percent, the time or the simulated note), the problems, and nothing about decisions, trades or money. `--save` writes the request, the intent, the path and the order WITH its `data`. A quote run is NOT saved to `data/proving/sessions/` and its capture goes in `tests/fixtures/quote_real/` (not `session_real/`, for the reason entry 149 gave: the offline evaluation's sessions dataset). |
| Q9 | **Nothing else changes.** Every other action, route and printed line is as it was; every existing test passes with no expected value changed, EXCEPT where a test pins the closed list of actions or the prompt text (say which, and why). No size limit, risk rule or liquidity rule. |

## 2. What changes, module by module

- `configs/account_manager_v1.json`: a section `quote` with `max_stocks` 10 (and its loader, beside `news`).
- `prometheus/agents/account_manager/intent.py`: `"quote"` in `action`; a `_quote_intent(raw, typed)` beside `_news_intent` (Q2; refuses a topic and every money field; checks the stocks are the user's words as `news` does); `describe`/`what`/`as_request` for `quote`; module docstring bullet beside THE NEWS.
- `prometheus/prompts/account_manager_request.py`: `"quote"` in the action line, one bullet (made-up tickers), and the `news` bullet's line that a price is `quote`. Docstring paragraph.
- `prometheus/langgraph/desk.py`: `quote_plan` beside `news_plan` (`read_text` calls it before `confirm`), `quote_data` beside `news_data` (Q4, Q5), `after_data_clerk` and `path_finished` (Q3). Module docstring and graph picture.
- `prometheus/application/web/views.py` `quote_view` and `run_verdict`; `desk_run.py` emits `quote` and skips the decision/trade/money blocks; `emitter.py` the `quote` event and `LEVEL_OF_STATUS["quote"] = "good"`; `replay.py` plays a quote capture.
- `prometheus/application/session.py`: Q8.
- `ui/src/api/types.ts`, events, state (the run's `quote`), the main output's quote lines (the run box), styles in the page's existing look.
- `docs/design_choices.md` entry 150; `AGENTS.md` one sentence beside the news bullet; `HowToRun.txt` one example; `README.md` if it lists the actions.
