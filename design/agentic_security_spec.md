## 1. Rules

| # | Rule |
|---|------|
| S1 | ONE package `prometheus/security/`: `policy.py` (loads `configs/security_v1.yaml`), `rules.py` (code rules), `scorer.py` (the LLM Risk Scorer), `router.py` (`act(risk)` and `trust_score(...)`), `guard.py` (the doors below), `audit.py`, `rate.py`. Every threshold, pattern list and message is in `configs/security_v1.yaml` (YAML: add `pyyaml` to `requirements.txt` only if it is not already a direct dependency; check `pip show pyyaml` first). |
| S2 | THE RISK SCORE is in [0, 1] and is the MAXIMUM of the code rules' scores and, when the LLM scorer is used, its score. Code runs first; if a code rule already gives >= the BLOCK threshold, the model is not called. |
| S3 | THE ROUTER (week 6 class example, thresholds in the YAML): `risk >= 0.8` BLOCK, `>= 0.5` REDACT_OR_REVIEW, `>= 0.2` ALLOW_AND_FLAG, else ALLOW. `act` is a pure function. |
| S4 | WHAT AN ACTION DOES. For a USER REQUEST: BLOCK refuses the run with the policy's message; REDACT_OR_REVIEW also refuses it in both modes (fail closed: there is no operator console yet; the audit log marks it `review` so a person can look later) with a message that says it was held for review; ALLOW_AND_FLAG runs and is logged as flagged; ALLOW runs. For a DOCUMENT (news, press release, filing text): BLOCK and REDACT_OR_REVIEW drop it from the evidence (logged with its id and the rule), lower actions keep it. For a MESSAGE TO THE USER: secrets and another account's number are REDACTED in place (`[redacted]`), the rest is shown. |
| S5 | FAIL CLOSED. If the LLM scorer is configured and its call fails or its reply is not valid JSON in range after one retry, the request's risk is the YAML's `scorer_failure_risk` (0.5: held for review). Code rules never fail open: an exception in a rule is risk 1.0 for that input, logged. |
| S6 | THE LLM RISK SCORER: role `guard` in `prometheus/models/chat.py`, setting `GUARD_MODEL`, default `qwen/qwen3.8-max-0902` (a large Qwen on OpenRouter, JSON mode supported; the design names Qwen), temperature 0. Its prompt lives in `prometheus/prompts/guard.py`: the user's text is DATA inside clear delimiters, the model returns `{"injection": x, "personal_data": x, "policy": x, "off_topic": x, "reason": "..."}` each in [0, 1]; CODE takes the max of the first three, maps `off_topic` to at most the REVIEW band (min(off_topic, 0.79) — off topic is review, never block, per the submission), checks ranges and keys. The model only labels; the number and the action are code (entries 24, 26). |
| S7 | THE TRUST SCORE (reliability, never blocks anything): `trust = 0.4*grounded + 0.2*(source + confidence + history)` per recommendation, each signal in [0, 1] from data already on the work order: `grounded` = share of the recommendation's citations that pass the citation check; `source` = share of its evidence from registered sources (Finnhub, Massive, EDGAR); `confidence` = the Advisor's score / 100; `history` = the ledger's past hit rate for the symbol if one exists, else 0.5. It is recorded on the audit log and in the trace (a `security.trust_score` span), shown nowhere else in v1, and changes no decision. |
| S8 | THE AUDIT LOG: append-only JSON lines, one per screened input, at `logs/security_audit.jsonl` (gitignored; the folder is created when missing): time (UTC ISO), door (`request`, `document`, `message`), account id when known, action, risk, the rule ids and the scorer's reason, a SHA-256 of the text and at most its first 200 characters — never a key, a password or a whole document. A write that fails is printed to stderr once and never stops a run. |
| S9 | THE RATE LIMIT (spam and SLA protection, submission question 1): per account id (or `"cli"`), at most `max_requests_per_minute` (default 6) and `max_requests_per_hour` (default 60) user requests, in memory per process; over the limit the request is BLOCKED with its message and logged. In the web bridge it applies to `POST /api/runs` (HTTP 429 with the message); in the session to the one request (it can only trip in a test). |
| S10 | THE CODE RULES (YAML ids, each with a score), for a user request: `sql_or_ddl` (SELECT/INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/TRUNCATE/GRANT as SQL, `;--`, `UNION SELECT`: 0.9); `prompt_injection` ("ignore/disregard/forget (all) (previous|prior|above|your) instructions/rules", "you are now", "system prompt", "developer mode", "jailbreak", role markers `<|im_start|>`, `### system`, `assistant:` at a line start: 0.9); `other_account` ("another user's", "all accounts", "every account", "other customers", an account number that is not the requester's when the account is known, "list users", "dump": 0.9); `export` ("email", "send to", "upload", "export", "webhook", a URL or an e-mail address in the request: 0.8); `live_trading` ("real broker", "live account", "disable paper", "PAPER_TRADING": 0.9); `secrets` ("api key", "password", ".env", "secret", "token" as a request to show one: 0.9); `market_abuse` (insider information, pump and dump, spoofing, wash trade, front-run: 0.8); `hidden_text` (zero-width or bidi control characters, base64 blobs over 200 chars: 0.6); `too_long` (over the request reader's limit: already refused by `check_typed`, keep it there). For a DOCUMENT: `prompt_injection`, `hidden_text`, and `addressed_to_ai` ("as an AI", "language model", "LLM", "assistant" combined with an imperative such as "must", "should now", "recommend buying": 0.8). For a MESSAGE: `secrets` patterns (`lsv2_`, `sk-`, `postgres://`, `password=`) and account numbers that are not the user's. Patterns are case insensitive and whole-word where it matters. |
| S11 | FALSE POSITIVES ARE BUGS. Every real user request in `tests/fixtures/session_real/*.json` and `tests/fixtures/*request*`/`*forms*` captures must screen ALLOW by code rules, and the document rules run over EVERY stored news, press release and filing record (`rag/loaders.load_news` etc. on the real files under `news/`, `data/press_releases/`, `data/filings/`; read only, never written) must drop at most 0.1% of them: the test prints the ones it drops with the rule, and each one must be read by the worker and judged a real hit or the rule tightened. |
| S12 | NO BEHAVIOUR CHANGE FOR AN ALLOWED REQUEST. The desk, the decisions, the sizing, the trades, the printed lines and every existing test stay the same for a request that screens ALLOW or ALLOW_AND_FLAG. The guard is injected: `build_desk(..., guard=None)` uses `Guard.code_only()` (rules, router, audit off by default in tests via `PROMETHEUS_AUDIT=false` set in `tests/conftest.py`), and the real parts (`session.build_parts`, the web's `desk_run`) build `Guard.with_scorer()` (rules + LLM + audit). |

## 2. The doors (where the guard runs)

1. **The user's request** — `langgraph/desk.py`, the `account_manager` node, right BEFORE `manager.understand_request(ask.get("text"))` (line ~328): `verdict = guard.screen_request(text, account_id=...)`. BLOCK / REDACT_OR_REVIEW return `{"order": None, "errors": [verdict.message], "plan": None, "clarify": False, "security": verdict.as_dict()}` (add `security: dict` to the desk state); the session and the web page already print a run's errors. Add the rate limit check first (S9).
2. **The documents** — where the Data Clerk's retrieved evidence is put on the work order (find it: `DataClerk.request_data` and the retriever's results it collects). Each document's text is screened by `guard.screen_document(...)` with CODE RULES ONLY (no model call per document: cost); a dropped document is removed before the Advisor sees it, counted on the work order's data stats (`security_dropped`), logged. Also at ingest: `rag/loaders.load_news`/`load_press_releases` add a `Skipped` with reason `security:<rule>` for a record that BLOCKs (the ingest already prints what it discarded, entry 83). Filings keep their strict rule plus this scan at retrieval only.
3. **The messages to the user** — `AccountManager.tell_user` (the Account Manager is the only agent that talks to the user) and the web bridge's final message (`application/web/views.py`, the place that builds the text the page shows): `guard.screen_message(text, account_id)` redacts (S4). The session's own report printing is NOT changed in v1 (open item).
4. **The Trust Score** — after the Critic's reviews exist (the `critic` node's output or `decisions.decide_trades`' input), compute S7 per recommendation, put it in the trace span and the audit log only.

Each door is a `traced("security.<door>")` span (`prometheus/common/trace.py`, entry 115) so LangSmith shows the risk, the rules and the action of every screen.
